## 1. Project Overview

### Vision

Agente de automatización diario que monitorea YouTube por canales específicos y/o temáticas configurables, selecciona los videos más relevantes (combinando popularidad y frescura), los resume con IA y envía un digest completo a WhatsApp. El usuario recibe cada mañana un briefing de los mejores contenidos de YouTube sin tener que buscar nada manualmente.

El sistema corre de forma autónoma en Railway, se activa a las 08:00 cada día y sólo requiere editar un fichero YAML para añadir o quitar canales y temas de búsqueda.

### Goals

- Monitorear canales concretos de YouTube y temas por popularidad de forma combinada
- Resumir cada video con Claude en 5 puntos clave en español
- Enviar a WhatsApp: primero digest global, luego detalle por video
- Evitar repetir videos ya enviados (memoria en SQLite)

### Success Metrics

- El agente se ejecuta sin errores diariamente a las 08:00
- Cada ejecución entrega entre 3 y 7 videos relevantes (no más, no menos)
- Los resúmenes son útiles, concisos y en español correcto

## 4. Data Model

### Entidades

**sent_videos** — historial de videos ya procesados y enviados

| Campo | Tipo | Notas |
|-------|------|-------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT |
| video_id | TEXT | ID único de YouTube, UNIQUE |
| title | TEXT | Título del video |
| channel_name | TEXT | Nombre del canal |

| Campo | Tipo | Notas |
|-------|------|-------|
| id | INTEGER | PRIMARY KEY AUTOINCREMENT |
| executed_at | TEXT | ISO 8601 timestamp |
| videos_found | INTEGER | Total videos encontrados antes de filtrar |

| status | TEXT | 'success' \| 'partial' \| 'error' |
| error_message | TEXT | NULL si status = success |

### Schema SQL

```sql
CREATE TABLE IF NOT EXISTS sent_videos (

    video_id TEXT UNIQUE NOT NULL,

    channel_name TEXT NOT NULL,
    channel_id TEXT NOT NULL,
    published_at TEXT NOT NULL,
    view_count INTEGER NOT NULL,
    sent_at TEXT NOT NULL,
    summary TEXT

CREATE TABLE IF NOT EXISTS execution_log (

    executed_at TEXT NOT NULL,
    videos_found INTEGER NOT NULL DEFAULT 0,
    videos_sent INTEGER NOT NULL DEFAULT 0,
    status TEXT NOT NULL DEFAULT 'success',
    error_message TEXT
);
```

## 6. Algoritmo de Selección de Videos

El `selector.py` aplica un score compuesto para elegir los mejores videos:

```
score = (views_normalized * 0.6) + (recency_normalized * 0.4)
```

- `views_normalized`: vistas del video / máximas vistas del batch (0.0 a 1.0)
- `recency_normalized`: 1.0 si publicado hoy, decrece linealmente hasta 0.0 en `max_age_days`
- Se toman los top N videos por score
- Se filtran videos ya presentes en `sent_videos` (SQLite)
- Si un video no tiene transcripción disponible, se salta y se toma el siguiente

## 8. Build Order

**Step 1: Scaffolding del proyecto**
```bash
mkdir youtube-whatsapp-agent && cd youtube-whatsapp-agent
python -m venv .venv && source .venv/bin/activate
pip install google-api-python-client youtube-transcript-api anthropic \
    twilio apscheduler pyyaml python-dotenv loguru
pip freeze > requirements.txt
```
Crear estructura de directorios vacía con `__init__.py` en cada `src/` subdirectorio.

**Step 2: Configuración y variables de entorno**
- Crear `config.yaml` con la estructura definida en Sección 5
- Crear `.env.example` con todas las variables (ver Sección 9)
- Implementar `src/config.py`: carga `config.yaml` con PyYAML, valida variables de entorno con python-dotenv, expone un objeto `Config` global con todos los valores tipados

**Step 3: Base de datos SQLite**
- Implementar `src/db/database.py`: función `init_db()` que crea las tablas si no existen
- Implementar `src/db/repository.py`: 
  - `is_video_sent(video_id: str) -> bool`
  - `mark_video_sent(video: dict, summary: str) -> None`
  - `log_execution(videos_found: int, videos_sent: int, status: str, error: str | None) -> None`

**Step 4: Cliente de YouTube**
- Implementar `src/youtube/client.py`: inicializa `googleapiclient.discovery.build("youtube", "v3")` con la API key
- Implementar `src/youtube/searcher.py`:
  - `search_by_channel(channel_id: str, max_age_days: int) -> list[dict]`: usa `search.list` + `videos.list` para stats
  - `search_by_topic(query: str, max_age_days: int) -> list[dict]`: usa `search.list` con `order=viewCount`
  - Cada video retornado: `{video_id, title, channel_id, channel_name, published_at, view_count, url}`

**Step 5: Selector de videos**
- Implementar `src/youtube/selector.py`:
  - `score_videos(videos: list[dict], weights: dict) -> list[dict]`: aplica el algoritmo de scoring (Sección 6)
  - `select_top(videos: list[dict], max_n: int, repo) -> list[dict]`: filtra ya enviados, toma los top N
- Probar el selector con datos mock antes de continuar

**Step 6: Fetcher de transcripciones**
- Implementar `src/transcripts/fetcher.py`:
  - `get_transcript(video_id: str, languages: list[str] = ["es", "en"]) -> str | None`
  - Intenta español primero, luego inglés, luego el primero disponible
  - Retorna `None` si no hay transcripción (video se saltará)
- Implementar `src/transcripts/cleaner.py`:
  - `clean_and_truncate(transcript: str, max_chars: int) -> str`: elimina timestamps, normaliza espacios, trunca

**Step 7: Summarizador con Claude**
- Implementar `src/summarizer/claude_client.py`:
  - Usa `anthropic.Anthropic()` con el modelo `claude-sonnet-4-6`
  - Función `summarize_video(title: str, channel: str, transcript: str, config: Config) -> str`
  - Prompt: dado el título, canal y transcripción, extrae exactamente N puntos clave en español
  - Incluir prompt caching (`cache_control`) en el system prompt para reducir costes
- Implementar `src/summarizer/formatter.py`:
  - `format_bullet_points(raw_summary: str) -> list[str]`: parsea los puntos del response

**Step 8: Cliente de WhatsApp (Twilio)**
- Implementar `src/whatsapp/twilio_client.py`:
  - Inicializa `twilio.rest.Client` con Account SID y Auth Token
  - Función `send_message(to: str, body: str) -> bool`: envía un mensaje, retorna True si OK
  - Añade delay de 1s entre mensajes para evitar rate limiting de Twilio
- Implementar `src/whatsapp/message_builder.py`:
  - `build_digest(videos: list[dict], date: str) -> str`: mensaje resumen global
  - `build_video_detail(video: dict, bullet_points: list[str]) -> str`: mensaje detalle

**Step 9: Pipeline principal**
- Implementar `src/pipeline.py` — función `run_daily_pipeline(config: Config) -> None`:
  1. Fetch videos de canales configurados (searcher)
  2. Fetch videos de temas configurados (searcher)
  3. Combinar, deduplicar por video_id
  4. Puntuar y seleccionar top N (selector)
  5. Para cada video seleccionado: fetch transcript → clean → summarize con Claude
  6. Si transcripción no disponible: skip video, intentar el siguiente en la lista
  7. Construir mensajes (message_builder)
  8. Enviar a todos los destinatarios (twilio_client): digest primero, luego detalles
  9. Registrar en SQLite (repository)
  10. Log de ejecución (loguru + execution_log)
- Manejar errores: si Claude falla en un video, saltarlo y continuar. Si Twilio falla, retry x3.

**Step 10: Scheduler**
- Implementar `src/scheduler.py`:
  - Usa `APScheduler.BlockingScheduler`
  - Registra `run_daily_pipeline` con `CronTrigger(hour=config.schedule.hour, minute=config.schedule.minute)`
- Implementar `main.py`:
  - Llama `init_db()` al arrancar
  - Arranca el scheduler
  - Log de inicio con próxima ejecución programada

**Step 11: Dockerfile y Railway**
```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "main.py"]
```
- Crear `railway.toml` con `[deploy] startCommand = "python main.py"`
- Crear volumen persistente en Railway para `/app/data/` (SQLite y logs)

**Step 12: Test end-to-end local**
- Crear `test_run.py` script que ejecuta el pipeline una vez inmediatamente (sin scheduler)
- Verificar: YouTube devuelve videos → transcripciones se descargan → Claude resume → Twilio envía
- Confirmar que reciben los mensajes en WhatsApp Sandbox
- Revisar `data/history.db` que los videos quedaron registrados

**Step 13: Deploy a Railway**
```bash
# Instalar Railway CLI
npm install -g @railway/cli
railway login
railway init
railway up
# Configurar variables de entorno en Railway dashboard
```

## 15. Reglas No Negociables

1. **Nunca commitear secretos.** `.env`, `data/history.db` y `logs/` en `.gitignore` desde el primer commit.
2. **El pipeline es tolerante a fallos.** Un video sin transcripción, una llamada fallida a Claude o un error de Twilio NO deben detener el pipeline — loggear y continuar.
3. **Idempotencia garantizada.** Consultar siempre SQLite antes de procesar un video. Re-ejecutar el pipeline no genera duplicados en WhatsApp.
4. **Transcripciones acotadas.** Truncar siempre a `max_transcript_chars` antes de enviar a Claude. Sin esto, los costes de API son impredecibles.
5. **Config en YAML, secretos en `.env`.** Ningún valor hardcodeado en código. El `config.yaml` es editable por el usuario final sin tocar Python.
